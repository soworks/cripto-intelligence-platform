## Recorders

Append-only JSON. One object per observation. The same identity and payload is a no-op. A different payload is refused. Failures go under `observation-failures/` and are not bars.

| Series | Family | Cadence | Provider |
|---|---|---|---|
| `btc_dominance` | `market_regime` | daily is enough | CoinGecko `/api/v3/global` |
| `stablecoin_supply` | `market_regime` | daily is enough | DefiLlama `stablecoincharts/all` |
| `funding` | `derivatives_positioning` | hourly | Binance public `fapi` `premiumIndex` |
| `open_interest` | `derivatives_positioning` | hourly | Binance public `fapi` `openInterest` |
| `spread`, `depth` | `execution_liquidity` | each scan | Spot depth on `data-api.binance.vision` |

Each file stores series, family, provider, source timestamp when the provider sends one, `observed_at`, symbol when the series has one, values, units, `schema_version`, and `collection_status`. Staleness is `observed_at`, not the schedule time.

`python -m cip.recorders run --output DIR` writes the local tree. The hourly scan does not call it yet. Futures traffic uses `https://fapi.binance.com`. From us-east-1 that host can return 451; the recorder stores the failure.
